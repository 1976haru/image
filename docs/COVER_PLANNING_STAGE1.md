# CoverMorph Studio 자동 음원커버 1단계

## 구현 범위

이번 단계는 채널 선택, JSON/TXT 가사와 자연어 요청 입력, 로컬 언어모델 해석,
서로 다른 커버 기획 4개 또는 5개 생성, 카드 수정·채택·제외·개별 재기획 및 프로젝트
저장까지다. 결과 카드는 완성 이미지가 아니다. 제목 데이터는 이미지 프롬프트와 분리되며,
SDXL 생성과 1400×1400 JPG 문구 합성은 다음 단계에서 연결한다.

기존 프로젝트 스키마 3의 선택 필드 `cover_planning`에 입력 스냅샷, 모델 설정, 처리 곡,
실패/누락, 해석, 결과와 이전 결과 이력을 저장한다. 기존 프로젝트와 이미지 변환·SDXL·
IP-Adapter 경로는 유지한다.

- 파일: `qwen2.5-7b-instruct-q4_k_m-00001-of-00002.gguf` (약 3.99GB),
  `qwen2.5-7b-instruct-q4_k_m-00002-of-00002.gguf` (약 690MB)
- SHA-256: 1부 `dfce12e3862a5283ccfb88221b48480e58745165de856439950d0f22590580db`,
  2부 `539cf93f78e887edea1c04e2d7d8cdaca9d01dae9c9025bcb8accbe29df3d72a`
- 엔진/양자화: 별도 프로세스 `llama.cpp` CLI, GGUF Q4_K_M, CUDA layer offload
- 라이선스: Apache-2.0
- 메모리: 모델 파일 약 4.68GB 외에 KV cache와 실행 여유가 필요하다. 기본 context는
  16,384 토큰이다. RTX 3060 12GB에서 실행하도록 정했지만 다른 GPU 작업과 동시에
  실행하지 않는다. 가사 합계가 큰 앨범은 모든 곡을 각각 LLM으로 요약한 뒤 통합 해석한다.

선정 이유는 한국어·일본어·영어를 포함하는 다국어 지시 수행, JSON 구조화 출력 능력,
상업적 사용에 명확한 Apache-2.0 라이선스, 12GB VRAM에서 운용 가능한 Q4_K_M 크기다.
공식 모델 저장소는 Q4_K_M의 llama.cpp 실행 예를 제공하며, llama.cpp는 JSON Schema
제약 출력을 지원한다.

- 모델 카드: https://huggingface.co/Qwen/Qwen2.5-7B-Instruct-GGUF
- llama.cpp 서버/구조화 출력: https://github.com/ggml-org/llama.cpp/tree/master/tools/server
- llama.cpp CUDA 빌드: https://github.com/ggml-org/llama.cpp/blob/master/docs/build.md

## 준비 및 사용 순서

1. 앱에서 새 프로젝트를 만들거나 기존 프로젝트를 연다.
2. `기획 모델 준비/다운로드`를 누른다. 앱 시작이나 가사 불러오기만으로 다운로드하지 않는다.
3. Windows용 CUDA `llama-cli.exe`와 DLL을 `tools/llama/`에 두거나 `llama-cli`를 PATH에
   설치한다. 공식 Windows 설치 방법은 `winget install llama.cpp`다.
4. 상태 확인에서 모델과 실행 파일이 모두 준비됐는지 확인한다.
5. 채널을 고르고 JSON/TXT를 불러오거나 주제/요청을 입력한다.
6. 후보 4 또는 5를 고르고 `커버 기획 만들기`를 누른다.
7. 카드의 장면과 제목을 수정 저장하고 채택/제외한다. 필요하면 한 카드만 재기획한다.
8. 프로젝트를 저장한다.

다운로드는 두 파일을 `.part`로 받은 뒤 예상 크기 이상일 때만 완료 파일로 바꾼다.
실행할 때마다 별도 `llama-cli` 프로세스를 사용하므로 작업 종료 후 모델과 GPU 메모리가
해제된다. SDXL 등 다른 앱 작업이 실행 중이면 CoverMorph의 기존 단일 작업 잠금이 새 기획
작업을 시작하지 않는다.

## 해석 및 검증 원칙

- 사용자가 명시한 세부 설정, 자연어 요청, 채널 기본값 순으로 우선한다.
- 선택된 곡만 보내고 각 곡 ID의 성공 여부를 요구한다. 누락 곡이 있으면 `partial`이다.
- 파일 내용은 창작 자료로 취급하며 그 안의 명령을 실행하지 않는다.
- 음악 프롬프트와 이미지 마스터 지침을 구분하고 BPM/악기를 이미지 문구로 복사하지 않는다.
- 원문 발췌 제목은 곡 ID와 정확한 원문이 실제 가사에 존재하는지 코드에서 대조한다.
- 제목은 별도 데이터이며 SDXL 프롬프트에 자동 삽입하지 않는다.
- 참고 사진은 ID·역할·강도만 연결한다. 텍스트 모델이 사진을 봤다고 표시하지 않는다.
- 형식 보정은 한 번만 재시도하며, 취소/실패 시 기존 기획을 덮어쓰지 않는다.

## 알려진 한계

모델 파일과 CUDA llama.cpp는 저장소에 포함되지 않는다. 실제 추론 품질 검증은 둘이 준비된
PC에서 수행해야 한다. 단일 곡 자체가 16K context를 크게 넘는 극단적인 경우에는 더 작은
구간 요약 개선이 필요할 수 있다. 얼굴 고정과 두 인물 독립 제어,
완성 이미지의 실제 밝기/품질 판정은 구현됐다고 표시하지 않는다.
